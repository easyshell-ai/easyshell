# 主机授权产品说明

> 状态：产品要求与安全边界；当前实现尚未发布，仍待验证。本文不表示相关能力已经上线或在所有入口生效。

## 目标与范围

主机授权用于限制用户对各台主机的可见性和操作能力，覆盖直接访问以及任务、工作流、终端等间接使用主机的入口。平台角色决定用户是否具备某类功能或管理资格，主机授权决定该用户是否可以对特定主机使用该能力；两者不能互相替代。

## 权限与授权主体

每项授权针对具体主机、授权主体和权限。授权主体可以是用户或角色：用户的有效主机权限为其直接获得的授权与其当前所有角色获得的授权的**并集**。角色成员变化应反映在后续授权判断中；没有匹配授权时拒绝访问。

| 权限 | 产品含义 | 不自动包含 |
| --- | --- | --- |
| `VIEW` | 查看获授权主机及其允许展示的主机信息。 | 执行任务、使用终端。 |
| `EXECUTE` | 在获授权主机上发起或参与平台支持的任务、脚本等执行操作，仍须满足相应功能权限和风险门禁。 | 终端交互；不因拥有该权限而绕过其他校验。 |
| `TERMINAL` | 在获授权主机上建立和使用交互式终端，仍须满足相应功能权限。 | 任务执行；不因拥有该权限而绕过其他校验。 |

三项权限应分别授予和检查，不因一种权限隐含另一种权限。需要同时展示主机信息和执行操作的界面或流程，应分别满足相关权限；不得因为列表隐藏了主机就省略服务端校验。

管理员可以管理主机授权，但**管理授权不等于拥有主机使用权限**。管理员查看、执行或使用终端时，也须针对该主机获得相应授权并通过其他适用的功能与安全检查。

## 存量兼容与新增对象

启用授权时，迁移必须保留存量用户对存量主机原有的实际权限，不能仅按新权限名称或对旧角色的直觉推断。尤其是旧 `viewer` 原先具有的执行能力也必须保留，不能因为角色名为 viewer 而丢失。迁移应以旧系统真实授权规则和迁移时的用户、角色、主机关系为依据，记录可核查的迁移结果；无法可靠确定的情况须显式标记并处理，不得猜测或静默扩大权限。

迁移完成后，新用户和新主机**不自动获得主机授权**：新用户不会仅因已有主机而取得访问权限，新主机也不会仅因已有用户或角色而自动对其开放。管理员需按实际需要显式配置授权；这不影响随后通过已明确配置的角色授权参与并集计算。

## 安全边界

- **迁移切换**：迁移必须可核查、可重复执行且避免部分迁移造成越权或误拒。切换前应核对存量权限映射，切换期间防止授权数据与用户、角色、主机变更产生不可见的差异；失败或无法确认时不得以默认放行兜底。
- **执行与间接入口**：服务端应在实际使用主机的边界检查对应权限，不能只依赖页面、创建时检查或调用方声称的身份。任务、定时任务和工作流等异步或间接执行路径需要明确执行身份，并在实际执行前重新检查；身份或授权无法确认时拒绝执行。
- **授权撤销**：撤销直接授权或角色成员关系后，后续访问和新执行须按最新有效权限判断；仍由其他用户或角色授权覆盖的权限不因单条授权撤销而消失。系统应阻止已失权用户继续使用现有终端会话，并在后续敏感操作边界重新校验；撤销不能承诺回滚已经完成的操作。
- **终端不可逆性**：终端中已经执行的命令及其外部影响不可因撤销授权而撤销。关闭会话只能阻止后续交互，不保证中止已经启动的远程进程或恢复其副作用。
- **历史数据身份**：历史任务和报告的执行身份若为 `unknown` 或无法可靠确定，不得根据创建人、当前角色、主机归属或其他线索猜测身份并补授权限。历史记录和报告的访问应遵守独立的数据访问控制，不能因身份未知而默认开放；需要补全时须依据可信证据并留痕。
- **审计与敏感信息**：授权变更、迁移及拒绝访问等关键事件应可审计；审计和文档不得记录密钥或其他不必要的敏感内容。

## 发布与验收

本文描述目标行为，不构成实现完成或发布承诺。发布前须验证各入口及异步执行的服务端检查、用户与角色授权并集、管理员使用限制、旧 viewer 执行能力迁移、新对象默认无授权、撤销后的访问与终端处理，以及历史身份未知时的拒绝和审计行为。迁移、并发变更和失败场景也须验证；验证未完成前不得将此能力描述为已上线。
