# 主机访问体验重设计（评审定版，待实施）

## 目标和范围

面向个人及团队，默认以主机为授权单位，日常界面提供「只读」和「可操作」两个授权预设。工作流选择器只列出当前用户可执行的主机。本文经独立安全复审修订，仅定义目标，不表示已有实现完成。现有数据、Agent 和历史运行必须保留。

## 产品契约

| 级别 | 主机能力 |
| --- | --- |
| 只读 | 本主体授予 `VIEW`。 |
| 可操作 | 本主体授予 `VIEW + EXECUTE + TERMINAL`；终端风险必须明确确认。 |

授权主体为用户或角色，对当前有效授权取并集；管理员负责管理授权，但管理权不自动代表主机使用权。新用户和新主机默认无隐式授权。撤销一个来源时，其他来源仍可能有效，界面应显示来源和有效结果。权限查询失败、身份缺失及主机代次不一致均拒绝。

保留现有平台角色上限，不静默扩大角色能力。viewer 原有 `EXECUTE` 保留，但目前不能授予或使用终端；因此不可把其现有 `VIEW + EXECUTE` 冒充完整可操作档。操作预设不可用于被禁止终端的主体，应明确说明原因并保留现有授权。文件代理目前另限 admin/super_admin，不能承诺所有可操作用户均可使用。界面分别显示授权行及叠加角色、身份和资源归属限制后的实际有效能力；管理授权不等于主机使用权或审批权。

## 工作流、终端与风险

- 创建或编辑时仅展示当前用户可执行的主机；已保存但现无权限的目标应显示不可用提示，不得静默删除或改写。运行主体是 `run.startedBy`，主体缺失、禁用或失权时拒绝，不换主体补派。服务端在创建任务前解析全部真实目标并校验权限与 generation；任一不通过则不创建可派发任务且不发送。提交后网络发送不能跨主机原子保证：撤权、离线或发送失败可能造成部分发送，须记录每目标结果，未知结果不得自动重派。
- 显式主机选择区分加载、失败和无可选主机；失败或空列表不自动退回看似已授权的自由输入。集群、标签和变量等动态目标应提示运行时逐台解析校验，不能将编辑时的结果当作将来执行授权。
- 现阶段不新增跨用户共享运行或服务身份。保留工作流的既有 owner/admin 数据校验；管理员管理能力不暗示其具备任意主机使用权。
- `TaskServiceImpl.createAndDispatch` 继续是唯一风险门禁；主机可操作不代表批准高风险脚本。审批必须绑定最终意图并一次性消费，未完成时保持拒绝。
- 可操作包含交互终端：用户可在终端内直接执行命令；现有任务/工作流风险门禁不覆盖终端输入。界面和文档不得声称所有高风险命令均需审批。应保持会话授权检查与审计，撤权不保证撤销已发生的远程副作用。
- 取消是逻辑取消，不宣称已终止远程进程；未知执行结果不得自动重派。

## 现有授权和兼容

不能将旧 VIEW 自动扩展成执行或终端，也不能因模型转换剥夺旧 EXECUTE 或 TERMINAL。保留现有独立权限行：恰好匹配只读或可操作组合时用对应档展示，其他组合展示「历史自定义」，其真实权限不变；明确显示用户和角色的授权来源及合并结果。管理员显式选择目标档时，在事务中进行差异确认、原子变更、generation 校验及同步审计；角色授权的变更须提示对当前及未来角色成员生效。

复用现有存储并保持旧单项 API 的单项语义，尤其不能将单项撤权转为整组撤权。标准档变更需要单事务、主机 generation 和授权集版本 CAS（或等价串行化），在同一事务校验差异并同步审计；单靠 generation 无法防止并发管理员覆盖。旧客户端或旧实例不得绕过新协议的并发保护，混版未验证前禁止混跑。保留未知历史来源的拒绝策略，禁止回填可信来源。不得修改已运行的 Flyway 迁移；若必须新增迁移，使用新版本、失败关闭、支持多实例并发，并先在授权旧库副本验证。

原子接口设计：管理员读取一致的主机 generation、授权集版本及指定主体实际授权集合；提交预设时同时提交这些期望值及终端风险确认，服务端在主机身份锁内校验并原子更新指定主体、推进版本和同步审计。状态改变返回冲突，必须重新读取和确认。旧单项 API 保持原语义，但实际变更也必须在同事务推进授权版本；旧客户端自身没有 CAS，不能宣称其有预设级冲突保护。未知授权值不得被预设静默删除。新增版本与启动迁移、无变化操作、失败恢复及全部写入口的锁序须先冻结并测试；旧服务实例不推进版本，故未证明数据库级防绕过前禁止混跑。

历史授权的产生来源若无可信持久证据，只能称为「特殊权限」或「来源未记录」，不能根据权限组合推断为历史迁移。授权变更确认展示本条授权增减；实际有效权限取所有来源的并集，来源明细仅向有权查看的主体提供。

## 证据与发布门槛

- 服务端：用户/角色并集、只读及完整授权、历史特殊组合、撤销、版本兼容、用户/角色变更、generation、失败审计、数据库异常关闭；所有 REST、WS、任务、工作流、文件和 AI 入口与直接 SQL 查询结果一致。
- 前端：两档和历史特殊状态、授权来源、变更差异提示、查询失败不可操作、工作流可执行主机过滤、历史目标不可用提示；中英文文案同步。
- 并发与迁移：隔离 MySQL 测试授权变更、撤权、派发竞争与多实例切换；仅在受保护真实旧库副本上验证权限保留、差异、备份恢复和回滚边界。不得连接现有演示库或卷。
- 风险：普通 AI 审批与工作流高风险审批未完成精确绑定前持续拒绝；Agent 逐台身份尚未闭环，code 沙箱继续关闭。
- 授权矩阵覆盖所有旧三位组合、四种角色和用户/角色并集；终端建连、双向转发、撤权与 Agent 侧 PTY 清理均须验证。现有时点检查不保证撤权与发送原子一致或即时清理远端 PTY。
- 冻结候选后运行 `AGENTS.md` 全套检查，并在明确授权范围只对测试主机执行最简单只读查询。全部发布阻断和恢复演练关闭前不得更新演示环境。
