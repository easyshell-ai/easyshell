# 权限改造后的功能接线检查

2026-11-12检查重点是“正常授权用户仍被无条件拒绝”的占位，不是取消权限边界。

## 本轮补齐

- 首页脚本/任务统计：按当前用户可见范围聚合；不计未知目标来源，不返回脚本正文。
- 标签编辑/删除：当前有效管理员且有全部关联主机VIEW，标签行锁与关联修改串行。
- 统一主机查询：返回有VIEW权限的当前Agent；不按IP或历史agentId合并SSH凭据。
- 软件探测解析：当前用户本人任务、内置脚本逐字匹配、唯一目标快照/代次、当前VIEW和
  EXECUTE、无工作流关联、唯一Job证据后才能写库存。来源标记本身不构成授权。
- code预演提示：运行上下文test-run是无副作用预演，不再误报隔离运行时不可用；实际
  代码执行走编辑器样例接口，与真实工作流共用远程隔离边界。

## 仍需完整协议的功能

本轮已在真实 MySQL 验证首页与授权统一主机列表、标签创建/关联/编辑/删除；测试 VM
恢复直接连接后，两次内置探测均成功解析9条库存记录，伪造任务ID解析返回403。
此前失败任务是心跳在线但WebSocket未连接，记录保留，不被算作执行成功。

- 普通任务高风险审批：现有待审批Task行不能证明一次性消费与实际脚本/目标代次/用户/
  timeout一致，当前唯一派发门禁拒绝其豁免。工作流精确审批已实现，不能用它的通过
  结果宣称普通任务审批也可派发。需补普通任务证据协议、决定接口和原子消费回归。
- 外部聊天渠道入站：Telegram/Discord已补默认关闭的部署侧稳定ID绑定、当前有效用户
  检查和无工具新会话路径，参见channel-user-bindings.md；未配置绑定仍拒绝。
  Telegram仅限本人私聊，Discord绑定频道与用户且核验平台单人私信元数据；该批改动
  已通过最终clean全量回归（1575项、0失败、0错误、5项条件跳过），平台真实收件未验收。
  Slack/飞书/钉钉的企业作用域与真实平台收件验收尚未补齐，不能接受请求自报userId。
- 历史凭据自动合并：缺少owner/generation证据不做猜测回填；现有受限部署记录入口保留。

## 合理的拒绝

目标权限撤销、主机代次变化、来源未知或损坏、审批过期、禁用用户、模型/通知未配置、
隔离服务不健康均应继续拒绝。管理员角色不能覆盖主机VIEW/EXECUTE或历史来源缺失。
测试通过不能被解释为所有外部通知渠道、所有模型供应商和每种配置已端到端覆盖。
