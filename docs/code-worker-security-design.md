# Code 节点隔离 Worker 安全设计与接口契约

> 状态：隔离执行链已实现，并在专用临时运行时完成 JS/Python、mTLS、取消、监督器失联回收及内存耗尽验收；产品工作流与浏览器试运行也已实际验证。同 JVM 实现已删除。生产构建、主机重启、证书运维及 systemd 模板仍未完成发布验收，不能把临时环境等同正式部署。下文的安全要求仍是准入条件，不得回退本地执行。

## 目标与边界

让工作流 code 节点及其单节点试运行将用户提供的 JavaScript/Python `main(input)` 作为不可信数据变换执行，并返回 JSON 数据；实际工作流与试运行使用同一安全边界。既有预演行为和公开 API 契约不因本文自动改变。主机操作仍须走 `script-exec` + agent；禁止 shell 回退、宿主对象注入或绕过现有命令风险门禁。变量引用仍受拓扑祖先规则约束，试运行输入由调用方显式提供，不假定存在上游输出。

## 隔离架构

server 在完成现有身份、角色及资源归属校验后，向内网 worker 控制面提交任务；控制面由受限的部署编排设施为**每个任务创建独立的一次性容器和进程**，结果返回后销毁。server 和 worker 均不挂载 Docker/containerd socket，不持有可直接操纵宿主容器运行时的凭据；任务容器更不得访问这些接口。编排设施是单独的受信任部署组件，其权限只限创建、监控、终止本工作负载，不能由任务代码访问。不可用时拒绝任务，不降级到 server JVM、本机子进程或共享容器。

每个任务容器必须具有独立 cgroup 硬限制：内存上限（含 swap 策略）、CPU quota 和 PID 上限；部署必须验证限制实际生效，不能仅依赖 JVM 堆限制。还需限制临时空间、文件描述符、请求/响应及日志大小。容器使用只读 root 文件系统、固定非 root UID/GID、禁止提权、丢弃所有 Linux capabilities、启用 seccomp 和适用的强制访问控制；不挂载宿主目录、服务账号 token、数据库凭据或持久卷。仅允许运行所需的有界临时存储，销毁时清除。任务容器默认无网络，包括 DNS、元数据服务和控制面；结果经编排设施提供的受限单次通信通道返回。容器隔离不是对内核漏洞的完整防护，需维护内核和镜像补丁，并评估更强隔离运行时。

容器内只运行 GraalVM Polyglot JS/Python：`HostAccess.NONE`、`IOAccess.NONE`，禁用环境变量访问、进程与线程创建、宿主类查找及原生访问，不注入宿主对象；输入输出仅通过受限 JSON 数据通道复制。超时先调用 `context.close(true)`，再由容器外监督器在短暂宽限后强制杀死任务进程及整个容器/cgroup，包括取消、客户端断连和控制面重启后的孤儿任务。不得信任任务内自报的超时或清理成功。

## 内部接口契约（拟定）

仅 server 可访问内部 `POST /internal/v1/code-executions`；该接口不是公网工作流 REST API。服务间使用双向 TLS、校验受信任服务身份和授权策略；证书由部署系统分发、轮换，失败即拒绝。禁止将用户 token、数据库密钥传入任务容器。控制面不信任网络位置或调用方提供的用户身份作为唯一授权依据。

请求 JSON：`requestId`（服务端生成的唯一 ID）、`language`（`javascript` 或 `python`）、`source`（代码）、`input`（JSON）、`timeoutMs`（在服务端配置上下限内）。限制源码、输入大小与 JSON 深度；拒绝未知字段、语言、非法值及超过上限的请求。调用方不能选择镜像、资源限制、挂载、网络、环境或执行命令。请求 ID 用于关联和幂等：同 ID 同内容不得重复执行，不同内容返回冲突；超时或连接中断后不得盲目重试，须先查询受限状态，无法确定状态则返回不确定失败。该语义不保证跨故障的恰好一次执行。

成功响应 `200`：`requestId`、`status: "succeeded"`、`output`（有界 JSON）。执行异常返回结构化 `status: "failed"` 和稳定错误码，不返回堆栈、宿主路径、源码或输入；超时返回 `TIMEOUT`，资源耗尽返回 `RESOURCE_EXHAUSTED`。认证失败 `401/403`，非法请求 `400`，超限 `413`，速率或并发额度耗尽 `429`（可带 `Retry-After`），依赖或安全配置不可用 `503`。取消与状态查询如需提供，须使用相同服务身份授权和 requestId 归属校验；取消是幂等的，并以容器终止为完成条件。公开 API 如何映射这些结果须在接线时另行确认，不得泄露内部细节。

控制面按服务身份及用户/租户上下文实施速率限制、公平调度和有界队列，并设置全局与每租户并发上限；每个并发任务仍各占一个独立容器，绝不复用进程、Graal context 或任务可写状态。排队也有截止时间；server 设置端到端 deadline，涵盖排队、启动、执行和清理。达到上限时拒绝而不是无限排队。任务结果、异常和诊断输出均受大小限制，避免内存或日志放大。

## 配置、部署与数据保留

默认禁用。只有服务身份、可信证书、编排权限、网络隔离、镜像、cgroup 内存/CPU/PID 硬限制及超时等必要配置完整且经过启动与持续健康检查，才可接受任务；缺失、无法验证或运行中失效时，相关实际执行请求返回 `503`，不降级。健康检查必须验证真实运行时策略，而非仅检查配置字符串；已运行任务按安全策略终止。预演如何继续提供须明确区分，不能伪称实际执行。

部署升级需保留现有数据库和持久卷，禁止为启用 worker 清库、重建或自动清理历史数据；`workflow_run`、`workflow_node_run`、`workflow_approval`、`audit_log` 永久保留。执行请求中的源码、输入和输出不得进入容器日志、指标标签或错误响应；复用现有 `SensitiveDataFilter` 及审计服务，不另造掩码或审计体系。持久化工作流结果仍遵循既有契约和权限，不能因临时任务清理而删除历史记录。临时任务文件和短期幂等状态的生命周期必须有界，且不得误删上述永久数据。

## 实现前验收计划

- 契约及授权：合法 JS/Python JSON 结果、无效和超大请求、服务身份伪造、跨资源访问、幂等冲突、断连及状态查询；若新增带路径变量的公开端点，按 `AGENTS.md` 配数据级校验和逐端点非所有者 403 测试。
- 沙箱对抗：尝试宿主类、文件、网络、环境、进程、线程及原生访问均失败；无限循环、内存耗尽、fork/线程膨胀、超大输出均被外部限制并清理，server 和其他任务保持可用。
- 隔离与韧性：实测每任务 cgroup 限额、无 socket/凭据、只读 root、非 root、无网络；并发任务互不读写，达到限额得到 429；超时、取消、worker/编排重启后无孤儿进程或容器。
- 故障关闭：逐项移除或破坏证书、编排、资源限制和网络策略，验证返回 503、无同 JVM/本机回退；验证日志与错误不泄露源码、输入和敏感数据。
- 部署回归：使用已有持久数据升级及回滚，核对永久保留表和卷未受损；实现后运行 `AGENTS.md` 指定的 server 全量测试及受影响组件测试，并增加真实隔离环境集成测试。此处仅列计划，尚未执行或证明通过。
