# 容量建议与节点验证范围

以下为2026-11-12候选的验证边界，不是所有场景均可用的保证。

## CPU与内存

尚未在逐步压低CPU/RAM的独立机器上完成容量拐点测试，因此没有实测“绝对最低配置”。
小规模、低并发、MySQL/Redis/server/web同机建议从2 vCPU/4GiB RAM起步；启用Python
code、较多Agent、LLM链路或需要构建的机器建议4 vCPU/8GiB以上。这是初始容量建议，
不是已在该规格完成压力验收。构建机需求与运行机需求不同；磁盘还需预留镜像、数据库、
日志、备份及更新空间，不能只按程序大小分配。

code每任务容器512MiB硬内存上限、禁swap、1CPU配额、128PID、256MiB最大Java堆，
当前执行槽串行。正常小样例JS峰值约94–96MiB，Python约266–306MiB；不能按样例峰值
设置生产硬上限。Python冷启动约5.6–5.7秒，详见code-worker-performance.md。
这些任务限制不是整个系统最低配置。LLM在外部OpenAI协议服务运行，本机未承载模型。

## 节点覆盖

| 节点 | 已有证据 | 不能据此推断 |
|---|---|---|
| start/end/transform/condition | 执行器单测、真实引擎H2集成、图与变量引用契约 | 任意配置组合已全部穷举 |
| wait | 真实API运行与引擎取消/超时集成 | 任意跨进程长等待均可恢复 |
| script-exec | 两台授权VM真实LOW脚本、HIGH批准、拒绝不派发、目标代次/ACL负例 | 任意主机/脚本均安全或可执行 |
| approval | 真实批准/拒绝/重放409、到期及事务回滚、持久领取 | 任意UNKNOWN自动裁决或exactly-once |
| ai-analyze/llm/classifier | 执行器/严格JSON/分类门控测试；真实模型文本、JSON、分类及脚本输出传模型 | 所有供应商、schema、模型异常均已端到端覆盖 |
| code | JS/Python真实隔离、样例/工作流、mTLS、取消、OOM、回收、重启 | 所有语言库可用；guest文件/网络/进程等本就被禁用 |
| notify | 执行器及路由测试，区分delivered/failed/skipped | 每种外部通知平台已真实收件验收 |

不能用后端全量测试数宣称“每个节点都完成真实外部端到端验收”。外部通知、用户模型
配置及特定主机依赖需按部署场景验收。默认禁用或明确拒绝的能力不能当成可用功能。

## Git与发布

候选工作在feature/workflow-v2，本地分组提交不等于推送或合并。主分支名为main。
部署前核对真实远端分支、CI和合并结果；不以本地origin缓存推断已发布。

## 首页统计口径

首页主机数据按当前用户VIEW权限计算。脚本数按公开/本人创建/当前管理员读取规则计算，
任务统计与任务列表共用可信目标快照及完整主机VIEW条件；旧任务缺少快照不会被猜测为可见。
工作流派发任务目前由独立来源校验管理，不并入普通任务列表聚合，因此首页任务数不是
数据库所有task行数，也不等于工作流run数量。来源或权限不完整时应拒绝，不能用全局count
填补差额。后台查询失败时不能伪造零或继续展示“数据已更新”。
