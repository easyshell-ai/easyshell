# 隔离 code 任务的内存与启动测量

2026-11-12，在专用 Docker/cgroup v2 运行时，用固定 Temurin JRE21 镜像、
Graal 25.2.4、每任务新进程/新容器测量。输入为 `n=3`，输出为 `n=4`，
经 mTLS 控制面完成，25ms 采样可信宿主 cgroup `memory.peak`。

| 配置 | 语言 | 完整请求耗时 | 观察到的峰值 |
|---|---|---|---|
| 原 launcher，256MiB 最大堆 | JS | 1.394s | 95.6MiB |
| 原 launcher，256MiB 最大堆 | Python | 6.294s | 262.1MiB |
| 16MiB 初始堆、256MiB 最大堆、SerialGC、感知2CPU | JS | 1.343s | 93.8MiB |
| 同上，Python首次 | Python | 5.594s | 268.3MiB |
| 同上，三个独立任务 | Python | 5.711/5.729/5.632s | 305.9/269.0/265.8MiB |

这是小样本的启动优化证据，不能推断任意工作负载吞吐或声称内存下降。
最大堆不等于整个 JVM 内存；语言资源、类元数据、线程、直接内存和页缓存均计入
任务 cgroup。512MiB 内存上限、swap 禁用、CPU/PID 限额和一次性容器边界不变。
新参数已通过正常 JS/Python、两语言超时、取消、幂等和跨身份 mTLS 验收。

同日内核 OOM 日志明确为 `CONSTRAINT_MEMCG`，UID65532 的固定内存验收进程在
约512MiB任务上限处被杀；不是正常任务或宿主全局 OOM。随后任务恢复验证通过。
宿主约5GiB可用、memory PSI接近0，未执行 swapoff 或 drop_caches。清理仅限本任务
已停止 proof 容器、旧镜像和构建上下文，未终止其他服务或删除业务数据库。

后续性能预算应覆盖多次基线、同机交错 A/B、较大输入与输出、不同语言负载及并发背压；
不得把冷启动超时当 guest 超时通过，也不得通过共享 guest 状态或放宽权限减少启动开销。
