## 1. 产品定位与范围

### 当前事实

工作流已有编辑器、发布版本、手动运行、运行记录、审批中心，以及脚本执行、数据变换、条件、AI、代码、通知、等待等节点。它已经具备多步骤编排基础，但列表、节点配置和运行体验尚未完整解释其用途和限制。

### 本轮目标

**运维工作流是将一次运维处置整理为可重复运行、可判断、可审批、可追溯的 Runbook。** 它编排数据和步骤，不替代脚本本身，也不把 AI 的判断当作执行授权。

| 用户需求 | 产品边界 |
| --- | --- |
| 对一台或多台主机执行一次脚本 | **一次性任务**：选择脚本、目标和参数，执行并查看任务及日志。 |
| 保存、维护和复用脚本 | **脚本库**：管理脚本资产；工作流引用或固化其中的脚本，不再建立第二个脚本库。 |
| 多步骤采集、判断、审批、执行、通知 | **工作流**：组织以上能力，并记录使用的发布版本、触发人、节点和结果。 |
| 对话式分析问题、讨论处置方案 | **AI 对话**：辅助理解和规划；对话产出的内容不是审批，也不自动成为可执行脚本。 |
| 周期性 AI 检查并生成报告 | **AI 定时巡检**：现有独立产品；不应让用户误以为它已经能调度工作流。 |

列表和帮助入口应回答：“这条工作流解决什么问题、由谁在什么时候触发、会操作哪些主机、是否需要审批、如何查看结果。”优先从场景出发，再介绍节点。

### 暂不支持或待验证

- 工作流定时、Webhook、告警/任务事件触发，以及 AI 对话保存为工作流，当前没有可用产品入口。本轮不提供看似可用的入口；未来接入需单独定义身份、权限、幂等、限流和审计。
- 本轮不以节点数量、模板数量或 Dify 的视觉相似度作为成功标准；目标是一个真实、可理解、可验证的运维闭环。

## 2. 角色、可见性与触发

### 当前事实

| 事项 | 当前行为 |
| --- | --- |
| 列表可见性 | 非管理员可在列表中看到自己创建的工作流和标记为 public 的工作流；管理员可看全部。 |
| 工作流详情和变更 | 详情、版本及带工作流 ID 的操作要求属主或管理员；创建、修改、发布等写操作还受角色限制。 |
| 触发 | 目前是登录用户手动触发；要求 OPERATOR、ADMIN 或 SUPER_ADMIN，且工作流为本人所有或用户为管理员。默认运行当前发布版本。 |
| 运行记录 | 管理员、运行发起人或工作流属主可访问相应运行；具体接口仍须通过服务端校验。 |
| 审批 | 审批入口要求 ADMIN 或 SUPER_ADMIN。配置中可选择审批角色，但当前决策链未按单条审批的 `approverRole` 区分 ADMIN 与 SUPER_ADMIN；自审批目前允许，并在相关配置开启时记录警告。 |
| 主机与终端 | 基线没有用户到主机的细粒度 ACL，不能宣称工作流已逐主机授权。基线中的终端 WebSocket 允许 OPERATOR、ADMIN 和 SUPER_ADMIN；下述完整主机授权是目标，不代表当前实现已发布或验证。 |

因此，**public 目前只影响列表可见性，并不赋予非属主查看详情、编辑或触发的权限**。也不能将当前审批描述为“仅指定角色审批”或“强制双人复核”。

### 本轮目标

1. 创建、列表、编辑器和运行弹窗使用一致文案：当前触发方式为“手动”，以当前登录用户身份发起；发布不等于立即运行。
2. 可见性选择旁解释上述限制；无权操作时隐藏或禁用操作，并解释原因。前端提示不能代替后端授权。
3. 修复审批决策的数据级角色校验：要求 SUPER_ADMIN 的审批只能由超级管理员决策；要求 ADMIN 的审批由管理员或超级管理员决策。未获授权时返回 403 并审计。审批列表也应如实反映用户可处理的记录。
4. 明确展示发起人、审批人、审批状态和时间；在真正实现独立审批之前，不能宣称发起人与审批人必须不同。
5. 复用 `WorkflowAccess` 集中处理工作流数据级权限，不在 Controller 中另写所有权判断。若新增带路径变量的工作流端点，必须同时具备方法级角色权限、数据级校验、非所有者 403 参数化用例和端点清单更新。
6. **业主最终决定的完整主机授权**：对用户或角色与主机分别授予 `VIEW`、`EXECUTE`、`TERMINAL`，三种权限独立，不因拥有其中一项而自动获得其他权限。管理员负责管理授权，但管理员自身查看、执行或连接终端也须获得相应授权，不能仅凭管理员身份绕过。服务端须在主机查看、任务及工作流执行、终端 WebSocket 连接等实际入口校验相应授权，拒绝越权并审计；前端提示不能代替服务端校验。升级时保留既有用户×主机的旧有能力，不因迁移收紧原有访问；新增用户或主机默认无授权。迁移须保留现有数据，包括测试数据，不得为实现授权而清空或重建；迁移范围和结果须以旧能力及实际数据验证，能选择目标主机不代表已获授权。主机授权不替代既有风险门禁和审批要求。

### 暂不支持或待验证

团队共享、独立的“可运行/可编辑”授权、具体审批人或团队、服务账号和外部 token 均未作为本轮已有能力承诺。完整主机授权及其升级迁移仍须实现、发布前验证；临时阻断终端或仅隐藏入口不算完成。是否强制双人复核属于待决策的权限策略，不能仅靠文案或隐藏按钮实现。

## 3. 核心旅程：从真实数据到可追溯处置

### 本轮目标

面向一个真实场景，用户应能完成以下旅程：

1. **选择或创建场景**：说明用途、手动触发者、目标、输出和潜在副作用；选择已标识真实性的模板或空白开始。
2. **配置真实采集**：选择真实主机及人工编写的脚本，确认采集内容、参数和输出格式。没有在线 Agent 或实际采集结果时，显示缺失条件，不生成“正常”数据。
3. **AI 结构化判断**：选择上游真实输出和模型，声明希望得到的字段；显示模型调用、数据出站与脱敏提示。
4. **条件分支**：从可用上游输出选择判断字段、操作符和值；画布的 IF/ELSE 与实际连线一致。用户能理解未命中、求值失败和节点失败的区别。
5. **人工审批**：需要处置时，向有权审批的人展示请求、目标、依据、超时和决策状态；AI 建议不是授权。
6. **执行与通知**：审批通过后才进入需要人工授权的脚本步骤；任务结果与通知投递结果分别呈现，不把审批通过或工作流结束当作处置成功。
7. **追溯**：从运行详情查看触发人、发布版本、入参、节点状态、分支、审批、关联任务及输出；可进入任务详情并返回对应运行。

这是目标旅程，不意味着当前已经具备所有上述交互。真实主机执行、模型调用和消息外发均须由用户明确发起；示例数据只能用于明确标识的演示或测试。

**交付优先级**：本轮先验证手动触发的 AI 结构化判断→条件→真实多跳分支闭环；真实代码节点测试、从任务创建草稿等其他目标须独立实现和验收，不能因为写入本文就视为本轮必然交付。定时和事件触发不伪装接通。

### 低门槛起步

提供一个无需 Agent、模型或通知渠道的**演示流程**，例如手动输入状态，经条件分支和短暂等待后结束。它只演示编排，不宣称检查了主机。目标是在可用环境下，让首次使用的运维人员不读长文档即可在约五分钟内理解、发布并手动运行；是否达到该目标需通过可用性测试验证。

列表提供简短对照：“执行一次用任务；复用脚本用脚本库；多步骤、分支或审批用工作流。”帮助抽屉提供同一解释和一个真实数据场景。移除当前尚不存在的“从 AI DAG 计划导入”引导。

## 4. 列表、画布与模板

### 当前事实

- 列表可新建、编辑、发布、触发和归档；编辑器已有模板、帮助、变量选择器及 Config/Data/Docs 检查器。
- 只有 start/end 的画布会显示不可关闭的四步浮层，遮挡画布操作。
- 磁盘模板输出固定的示例使用率；健康检查模板使用固定的目标数量。这些不能代表真实检查。重启模板会执行真实主机操作，但并未验证重启后的服务状态。
- 脚本节点将同一任务的多个主机 Job 输出拼接后尝试整体解析 JSON；当前不能假定多主机输出天然是逐主机结构化结果。

### 本轮目标

1. 将四步浮层改为不遮挡画布的引导卡：可关闭、可选择不再提示、可从帮助重新打开。关闭状态按用户和工作流保存；存储不可用时仍可关闭，且不存放运行入参或凭据。
2. 模板卡明确标识**真实操作**或**模拟演示**，列出用途、所需 Agent/模型/通知渠道、可能执行的动作和创建后需配置的字段。应用已有内容的模板前保留替换确认。
3. 在真实实现和验证前，将固定数值模板标为模拟演示，不作为真实巡检推荐。真实磁盘/健康模板必须从实际目标采集数据、按输入参数判断；多主机语义未实现时明确限制范围，不用固定值补齐。
4. 涉及重启等主机变更的模板明确提醒真实副作用，并区分“审批通过”“任务执行结果”“服务验证结果”和“通知结果”。
5. 保存草稿、校验、发布、运行各有清晰说明；发布前显示真实校验结果及可定位的问题。校验请求失败、读取失败或没有草稿时显示“未完成校验”，不能显示“校验通过”。

### 暂不支持或待验证

模板市场、自动从任务/对话生成完整处置流程、真实多主机指标聚合均需单独实现和验证；不可用的能力不显示为可点击成功操作。

## 5. AI 结构化输出、变量发现和条件

### 当前事实

- LLM 可以请求文本或 JSON；JSON 解析失败会尝试一次修复。配置的 `jsonSchema` 当前只是模型提示，不进行服务端字段、类型或枚举强校验。
- 变量选择器和数据检查器已经存在，普通节点输出按拓扑祖先筛选；但 Start 输出分组目前无条件展示，未连接时也可能出现。LLM 已暴露整体 `json`，但不会从 Schema 自动列出其子字段。
- condition 的 IF/ELSE 已由出边 `sourceHandle` 真实门控。条件求值异常时当前会记录警告并按 false 处理；classifier 返回未知类别时节点失败，不能承诺自动走 default。
- **待动态验证的分支安全风险**：对此基线静态审查发现，引擎将 `skipped` 视为上游已结束，但普通出边门控未将其作为不可通行状态；未选分支的下游可能继续执行。不能因直接出边正确就认定多跳分支安全，必须用真实引擎回归复现、修复并验证后才能将其作为处置流程发布准入。

### 本轮目标

**LLM 配置**按“输入 → 模型 → 期望输出”组织：

- 输入使用现有变量选择器，展示来源、类型和可用范围；显示实际模型/默认配置的已知状态。配置查询失败、无权限和确实未配置应分别提示。
- 提供结构化 JSON 开关及字段表：字段名、类型、必填、描述、枚举；支持从用户提供的 JSON 示例生成，并保留高级原始 Schema。示例仅用于生成结构，不自动变成真实模型输出。
- 可视化编辑与原始 Schema 不得静默覆盖或丢弃不支持的约束；无法安全编辑时保留原文并提示。
- 将已声明且表达式系统实际支持的输出字段暴露给现有变量目录及 Data 检查器，例如 `nodes.analyze.output.json.needs_approval`。未声明、不可解析或未实现的路径不能冒充可用字段；非祖先节点的输出（包括未连接的 Start 输出）不得展示为可引用，工作流入参仍可按约定使用。祖先节点若因其他分支未执行，运行时的缺失也必须如实提示。

**条件配置**复用现有构建器：选择变量、操作符、固定值或另一变量，明确区分字符串、数字和布尔值；高级表达式仍是同一份条件值。模板引用使用 `${path}`，条件表达式使用裸路径；不新增第三套语法，也不要求在条件边上重复填写表达式。

例如以下内容**只是用户设计字段时的结构示例，不是真实分析结果**：

```json
{
  "summary": "示例说明",
  "needs_approval": true
}
```

条件可以选择该布尔字段并生成 `nodes.analyze.output.json.needs_approval == true`：IF 连向审批，ELSE 连向无处置结束。实际执行时只依据模型真实返回并通过相应校验的数据，不使用示例填充缺失结果。

为了让结构化字段可靠地驱动处置，本轮目标是为新配置提供明确、兼容旧定义的**严格结构化输出模式**：模型输出必须满足声明的必填、类型和枚举等已支持约束；不满足时显示失败，不得作为成功判断或静默进入正常分支。需要同时定义并测试失败传播，确保相关分支及其下游不会因 `partial` 等策略意外执行。旧定义继续明确标识“Schema 仅作提示”，不静默改变历史语义。

待评审的实现契约以显式 `outputMode: "json_schema_v1"` 区分严格模式，`jsonSchema` 为唯一 Schema 来源，字段路径仍使用 `nodes.<key>.output.json.<field>`。发布和运行复用同一受限 Schema 校验，拒绝远程引用、未知或不支持的关键字及超出复杂度限制的输入，并校验最终脱敏结果和输出大小；具体支持范围及限制应在实现中公开。非法 JSON、缺失字段、类型或枚举不符均失败，未知输出模式也必须拒绝。旧定义保持提示语义；旧客户端可能将新模式保存为旧模式，必须先确定并验证防降级和显式更改流程，不能静默降级。该契约尚待评审和实施，不代表现已支持。

当前 condition 的异常会进入 ELSE；在改变引擎语义之前，界面必须如实提示并展示警告，不能把 ELSE 文案等同于“正常/安全”。若为新流程提供“判断异常则失败、不选择任何分支”的严格模式，必须由后端真实实现、兼容旧流程并覆盖测试，不能仅在前端模拟。

在确认并修复上述 skipped 多跳传播风险之前，不能把流程宣传为安全的自动处置。修复后须保证未选分支的后续步骤持续跳过、不会创建任务或发送通知，同时允许确实有可通行入边的汇合节点按定义执行。

### 暂不支持或待验证

不承诺模型始终遵循 Schema、能自行决定执行权限，或能从任意复杂 JSON/数组自动发现可用路径。分类器的 default 不能宣传为未知模型类别的正常兜底；当前未知类别是失败。模型实际可用性、成本和外部数据处理仍需针对所选配置验证。

## 6. 代码节点与测试

### 当前事实

代码节点使用 JavaScript/Python 的 `main(input)` 和手工输入映射，在服务端 GraalVM 沙箱做数据变换。现有运行详情中的“单节点试运行”是预演：代码不会实际执行，LLM/分类器不会调用模型；脚本不会派发，且预演没有上游节点输出。

### 本轮目标

1. 检查器按“输入变量、代码、输出说明、测试结果”排列；新建时提供可编辑骨架。可复用现有 CodeMirror 和输入变量编辑组件。
2. 明确说明代码只用于数据变换；需要主机操作应使用脚本执行及既有风险/审批流程。
3. 提供真正的代码节点测试：用户填写或选择明确标识的样例输入，服务端复用与正式运行相同的沙箱，返回实际输出、耗时和错误；不派发任务、不推进真实运行或下游节点。
4. 结果明确标识“样例测试”及其时间，不能作为真实上游结果或发布成功的证明。最近真实运行另行标注版本、run 和时间；无数据时显示暂无。
5. 显示语法错误、入口缺失、运行时不可用、超时、输出不可序列化等真实状态，不伪造成功。输出字段声明或推断只用于发现与提示；是否强校验必须明确标识并由后端执行。

### 暂不支持或待验证

现有预演接口不满足真实代码/模型测试要求，不能只改按钮文案称其已支持。草稿整图运行、运行到此处、重跑失败节点、编辑真实运行变量及 pin/mock 上游数据不在本轮既有能力中；若未来提供，必须独立设计权限和副作用。

## 7. 脚本库、任务与执行回链

### 当前事实

脚本执行节点读取内联 `script`；前端的自由 `scriptId` 字段不会让后端执行所选脚本。任务页已有脚本库/手写模式、参数获取、主机/集群/标签选择及编辑器。脚本实体有递增版本号，但更新会覆盖原记录，当前不能据此取回历史脚本内容。

运行节点记录可关联任务 ID，但运行页现有任务链接携带的 `taskId` 参数未被任务页消费；任务页也未提供可靠的工作流回链。

基线之后的任务/报表 snapshot 和 run provenance 改动仍在进行中、未发布，不能据此宣称回链或历史数据访问已完成。历史任务或报告若来源未知，可能暂时无法安全显示；这表示来源或访问权限无法确认，**不代表数据已删除**，也不得通过删除数据解决。

### 本轮目标

- 脚本执行节点提供“手写脚本 / 脚本库”两种来源，选择后展示真实脚本、参数、目标和版本信息；复用现有脚本 API、目标选择和安全执行管线。后端未实现引用前，不提供貌似可执行的脚本库选择。
- 发布时由后端解析并固化被选择的脚本执行快照及来源标识、版本和内容指纹；明确告知“库中脚本后续修改不会改变已发布版本，更新需重新发布”。处理发布期间的版本竞争及不可访问/已删除脚本，不静默回退到最新内容或空脚本。快照是发布版本的执行证据，不是第二套脚本库。
- 旧定义中原本不生效的 `scriptId` 不得因新功能被静默激活；需区分新来源契约与历史数据，并验证旧发布版本行为不变。
- 任务页到工作流的首个入口可采用“从当前任务配置创建工作流草稿”，只创建草稿、不自动发布或执行；复制前提示人工检查目标、参数和风险。任务参数语法与工作流安全渲染存在差异，无法兼容时应指出并要求修正，不得绕过工作流渲染。
- 运行节点上的任务链接应实际打开该任务；任务详情展示可验证的工作流来源及返回入口。关联从服务端事实查询，不能信任 URL 自带的 run/node；任务与运行分别校验访问权限，缺关联或无权限时如实提示。
- 节点运行与任务的持久关联应在派发前事务性建立，覆盖并发、失败和取消；不能等节点结束后才补写，也不能从任务名称猜测关联。
- 保留真实执行输出、部分失败、审批和通知信息；敏感信息按既有出站规则处理。指纹与来源信息不得被包装成已验证的业务成功。

### 暂不支持或待验证

脚本历史版本浏览、引用影响分析、任务失败自动触发工作流不作为当前已有功能。脚本库当前接口可见性与未来共享策略须先核验，不能因为选择器能列出脚本就假定用户拥有执行或管理权限。

## 8. 草稿、发布、运行与结果

### 当前事实

- 发布把草稿变为不可变版本；发布后可能没有草稿，编辑器会回退展示当前发布版本，下一次保存才创建草稿。
- 列表触发表单当前取草稿定义，编辑器取当前画布定义；服务端默认执行当前发布版本。两者可能不一致。
- 运行记录包含版本、触发人、状态及节点记录。部分输出可能因类型或截断而无法在现有对象型展示中完整呈现，不能以空对象冒充真实输出。

### 本轮目标

| 用户操作 | 应呈现的语义 |
| --- | --- |
| 保存草稿 | 保存当前编辑内容，不改变正在运行或已发布版本；显示保存状态。 |
| 校验/发布 | 校验真正准备发布的草稿；仅在获得真实校验结果后显示通过、警告或阻断。发布后显示实际发布版本。 |
| 手动运行 | 读取并展示将运行的发布版本及其入参，展示当前触发身份。无发布版本或加载失败时阻止提交并给出修复入口。 |
| 确认与提交 | 表单从 `workflow.currentVersionId` 指向的已发布定义构造，请求显式携带用户确认的同一版本 ID；期间重新发布时不得悄然切换版本，若不能执行该版本则要求重新确认。一次提交的网络重试复用同一幂等键，服务端按工作流、版本和输入校验一致性，避免重复运行。 |
| 查看结果 | 区分等待审批、运行中、成功、失败、跳过、取消、超时及警告；显示真实输入/输出、版本、时间、attempt 和关联任务。 |

草稿是否有未发布修改应基于可靠比较或服务端事实；无法判断时显示未知，不以本地“已保存”冒充“已发布”。最近运行必须来自有权限的真实运行记录，标明版本和时间；空值、数组、标量和截断结果按实际形态显示。

### 暂不支持或待验证

发布后自动创建草稿、版本历史对比/恢复、运行草稿及选择任意历史版本作为用户功能，均不因已有底层字段或 API 就宣称已经可用。需要时单独确定权限、并发和不可变性契约。

## 9. 失败、超时与安全边界

### 当前事实

- 审批节点支持超时配置，包括 `approve`；超时结束与真实人工批准不是同一事实。
- 通知节点会分别记录 `delivered`、`failed`、`skipped`，即使渠道未投递，节点本身也可能为成功。
- 取消工作流是检查点传播及逻辑取消；已经派发给 Agent 的作业不能由此保证立即停止。

### 本轮目标

| 情况 | 产品行为 |
| --- | --- |
| 采集失败、目标不存在或离线 | 显示真实目标及错误；不生成替代指标，不把缺失数据判成正常。 |
| 模型未配置、不可用、超时或输出不合法 | 显示真实错误和可操作的修复建议；不使用示例或上次输出填充；严格判断模式按其失败传播契约阻止相关处置。 |
| 条件字段缺失或求值异常 | 明确展示警告及实际分支行为；不得将异常描述为正常。严格失败模式须后端真实支持。 |
| 审批等待、拒绝或超时 | 展示实际状态、截止时间与下一步；不把超时自动放行展示为人工批准，不将其作为人工执行授权。 |
| 脚本被风险门禁阻止、任务失败或部分失败 | 显示对应原因及实际任务/主机结果；不以 AI 建议或已通过的无关步骤绕过门禁。 |
| 通知失败、未配置或跳过 | 分渠道展示送达、失败或跳过及原因；节点成功不等于消息已送达。 |
| 用户取消或连接中断 | 显示取消请求和实际运行状态，明确已派发主机作业可能继续；连接断开不应被描述为任务已停止。 |

以下为不可突破的工程和安全硬规则：

1. 风险门禁唯一位置是 `TaskServiceImpl.createAndDispatch`；不新建第二道门禁、第二套命令白名单/黑名单。`449` 响应和审批风险字段只允许等级与模式串，禁止命令原文。新增 `DispatchAuthority` 调用方须显式更新对应架构测试。
2. AI/LLM 只产出分析或数据，不获得任务派发或执行授权；输出不得直接作为脚本 `rawParams`。AI/LLM 分析结果需要引出主机操作时，必须由人编写脚本并经过 `approval`；其他主机操作仍须遵循既有风险与审批规则。
3. 节点输出引用只能指向拓扑祖先；工作流入参按现有约定可用。发布期校验、运行期隔离与失败关闭均为权威，前端字段发现不能绕过它们，也不另建变量存储。
4. 代码节点只能复用 GraalVM Polyglot 沙箱：禁止宿主访问、IO、环境、进程及线程创建；禁止回退 shell 或注入宿主对象，超时必须取消上下文。
5. AI 输入/输出及需要脱敏的出站内容复用 `SensitiveDataFilter`，不另造掩码实现；不得在提示、日志或测试报告中暴露凭据。
6. 复用既有 `audit_log` 和 `AuditLogService`。发布、审批通过/拒绝、运行触发/取消等高危事件必须同步审计；工作流运行、节点运行、审批和审计记录永久保留。
7. 按资源 ID 建连的 WebSocket 必须在 `afterConnectionEstablished` 中校验归属，资源不存在或查询异常时拒绝；越权以 `POLICY_VIOLATION` 关闭并记录 WARN 审计，不得以页面可见性代替授权。

**审批证据的发布阻断**：基线尚不能证明批准证据绑定实际执行的脚本内容和目标；审批节点是祖先、显示“已批准”或风险等级相同都不足以证明此次派发已获授权。须先完成独立设计和验证，将人工决策与实际脚本快照、目标及相关执行上下文绑定，并覆盖变更、过期、拒绝和超时；在此之前不得演示或宣称高危处置可安全放行。AI 数据经分类器、变换或代码节点间接流入脚本参数时也不能绕过这些约束，最终派发仍经过唯一风险门禁。

### 暂不支持或待验证

本文件不承诺取消能够终止已派发作业，也不承诺审批超时配置、部分失败策略或通知失败会自动形成产品层的安全决策。任何更严格的默认策略须由后端实现并用测试证明，不能只靠 UI 描述。

## 10. 最低验收与交付约束

### 本轮目标

1. **定位与权限**：用户能区分任务、脚本库和工作流；手动触发及 public 的实际限制清楚可见。非属主和审批角色越权有服务端 403 与回归测试；不宣称已强制独立审批。验证用户及角色对各主机的 `VIEW`、`EXECUTE`、`TERMINAL` 独立授权，在查看、任务和工作流执行、终端直接连接等服务端入口拒绝越权并审计；管理员管理授权但自身使用仍需相应授权。覆盖升级前后既有用户×主机旧能力保持、新增用户或主机默认无授权，以及既有风险门禁和审批要求不被绕过。验证包括测试数据在内的既有数据保留；来源未知的历史任务或报告暂不可见不等于数据删除，不得以不可见冒充删除或以删除代替迁移。完整授权及迁移未实现并验证前，不宣称逐主机授权完成，临时阻断不能替代验收。
2. **首条流程**：无 Agent/模型的演示流程被明确标记为演示，用户可关闭并重新打开引导、完成发布和手动运行；不遮挡画布操作。
3. **真实 AI 分支**：用确定性模型替身验证结构化字段选择、IF/ELSE 实际连线及各自执行；用真实引擎覆盖未选分支多跳持续跳过、无任务/通知副作用以及分支汇合。另覆盖非法 JSON、缺字段、错类型、未知类别、异常和失败传播。真实模型的可选冒烟测试必须明确环境及结果，不得以模拟结果冒充。
4. **脚本和审批**：脚本库选择实际执行发布时确认的内容；库内修改不改变已发布快照。审批拒绝、超时、越权及风险阻断不被显示为人工批准或执行成功。
5. **代码测试**：真实运行用户提供的样例，展示真实结果；覆盖超时、运行时不可用、宿主访问拒绝、无权限及不派发任务/不执行下游。
6. **版本与追溯**：发布 v1 后修改草稿，从列表与编辑器运行均使用并显示用户确认的发布版入参；发布竞争、加载/校验失败和幂等重试均有覆盖。运行与任务可按真实关联双向跳转，并分别检查权限。
7. **真实与模拟**：模板、样例、最近真实运行和实际通知投递状态在界面中可区分；采集缺失、模型不可用、任务失败及通知跳过时不产生虚假成功信息。
8. **国际化与回归**：所有新增文案同时进入 `zh-CN.json` 与 `en-US.json`；按 `AGENTS.md` 执行相关 server、web、build、visual 等验证。视觉基线与样式变更同一提交，CI 安装并显式使用 CJK 字体；画布拖拽性能按规定的 P95 比率预算验证。

以上是目标验收，不是通过证明。发布前还需核验审批证据绑定、版本并发和不可变性、严格模式防降级及间接 AI 数据流；任一阻断项未解决时不宣称可发布。真实模型缺少凭据时单独披露，模型替身和预演不能替代真实模型或真实主机执行结果。
