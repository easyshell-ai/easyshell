# 外部渠道本地用户绑定

渠道入站默认关闭授权。部署者可通过受保护的 application YAML 配置显式映射，
配置前必须从已经认证的平台事件确认稳定主体ID；不得根据昵称、消息正文或用户自报ID绑定。

```yaml
easyshell:
  ai:
    channel-identities:
      enabled: true
      bindings:
        - channel: telegram
          external-id: '123456789'
          user-id: 7
```

示例ID仅为合成值，不代表真实授权。支持 Telegram私聊数字用户ID、Discord的
`channelId:authorId`数字复合主体，且平台元数据必须确认是单人私信频道；群组不允许，
必须由该服务配置的受信Bot身份获取事件。Slack、飞书和钉钉当前仍拒绝绑定，
直到企业/应用级主体作用域及可信认证路径逐一验收，不能用昵称兼容回退。

每条入站消息都检查映射唯一、本地用户存在且启用、角色有效。重复绑定、无绑定、
禁用用户均拒绝；删除映射并受控重启可撤销部署授权，禁用本地用户则下一消息即时拒绝。
此版本每条消息创建新的本人会话，不接受外部session ID，强制关闭所有AI工具，
不授予主机读取/执行能力。需要有工具的外部会话应另外设计逐资源授权和会话隔离。

内容与回复复用SensitiveDataFilter。失败不回显供应商异常。绑定单测和应用装配测试
不等同平台真实收件验收；需要Bot密钥的真实平台测试须单独记录，不能自动发送消息。

适配器回归使用内存 HTTP 响应验证私聊成功、群聊拒绝、主体/频道不匹配及元数据损坏，
不会访问真实平台。Discord 无法确认私信受众时连错误回复也不发送。
