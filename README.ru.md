# EasyShell

**AI-нативная платформа серверных операций**

Пусть ИИ пишет скрипты, управляет задачами на нескольких хостах и анализирует вашу инфраструктуру — пока вы фокусируетесь на главном.

## Почему EasyShell?

Традиционные инструменты управления серверами требуют от вас написания каждого скрипта, подключения по SSH к каждому узлу и самостоятельной интерпретации каждого вывода. EasyShell меняет эту модель: **ИИ выступает оператором, а вы — принимаете решения.**

- **Опишите задачу простым языком** → ИИ напишет готовые к работе shell-скрипты с проверкой изменений
- **Поставьте цель для нескольких хостов** → ИИ спланирует шаги выполнения, запустит их и обобщит результаты
- **Настройте плановые проверки** → ИИ анализирует вывод и самостоятельно решает, нужно ли уведомить команду через каналы ботов
- **Подключайтесь через Web SSH** → Полноценный терминал с файловым менеджером, вкладками и поиском — без локального клиента

## Основные возможности

### 1. AI Script Assistant

> Опишите, что вам нужно. ИИ напишет скрипт. Проверьте изменения. Примените в один клик.

AI Script Workbench — это редактор с разделенной панелью, где вы описываете требования на естественном языке, а ИИ генерирует или изменяет shell-скрипты для выбранной ОС. Написание скрипта отображается в реальном времени. Встроенный diff-режим подсвечивает все изменения. Вкладка сводки объясняет модификации на вашем языке.

<p align="center">
  <img src="docs/images/AI%20Script%20helper.png" alt="AI Script Assistant — генерация кода в реальном времени с проверкой изменений" width="90%" />
</p>

**Как это работает:**
1. **Описание** — опишите требования на естественном языке, выберите целевую ОС
2. **Генерация** — AI генерирует готовый к работе скрипт в реальном времени
3. **Проверка** — встроенный diff-режим подсвечивает все изменения; вкладка сводки объясняет модификации
4. **Применение** — один клик для сохранения в библиотеку скриптов или немедленной отправки

### 2. AI Task Orchestration

> «Проверь диск и память на всех хостах, отметь всё, что выше 80%, и предложи решения.» — Готово.

Интерфейс AI Chat позволяет ставить операционные задачи высокого уровня. ИИ разбивает их на многоэтапный план выполнения (исследование → анализ → отчет), отправляет скрипты на целевые хосты, собирает результаты и предоставляет структурированный анализ с оценкой рисков и практическими рекомендациями — и все это за один цикл общения.

<p align="center">
  <img src="docs/images/AI%20task%20orchestration.png" alt="AI Task Orchestration — многоэтапный план выполнения с анализом" width="90%" />
</p>

**Как это работает:**
1. **Инструкция** — опишите высокоуровневую цель в AI Chat (например, «проверь диск на всех хостах»)
2. **Планирование** — AI разбивает цель на многоэтапный план (исследование → анализ → отчет)
3. **Выполнение** — скрипты параллельно отправляются на целевые хосты, результаты собираются автоматически
4. **Отчет** — AI формирует структурированный анализ с оценкой рисков и практическими рекомендациями

### 3. AI-планирование проверок

> **Cron → Скрипт → AI-анализ → Интеллектуальное оповещение** — AI анализирует вывод и самостоятельно решает, нужно ли уведомить команду.

Планируйте задачи проверки с помощью cron-выражений и выбирайте скрипты из встроенной библиотеки. EasyShell отправляет их агентам по расписанию, собирает вывод (состояние диска, памяти, сервисов, логи), передает AI-модели для интеллектуального анализа, и **AI самостоятельно определяет, требует ли результат оповещения** — уведомления отправляются только когда это действительно необходимо.

<p align="center">
  <img src="docs/images/schedule_task.png" alt="AI-планирование проверок — задачи на основе cron с AI-анализом и интеллектуальным оповещением" width="90%" />
</p>

**Как это работает:**
1. **Настройка** — cron-выражение + скрипт (из библиотеки или пользовательский) + промпт для AI-анализа + правила уведомлений
2. **Выполнение** — EasyShell отправляет задачи целевым агентам по расписанию
3. **Анализ** — Вывод отправляется AI-модели (OpenAI / Gemini / GitHub Copilot / Custom) для интеллектуального анализа
4. **Уведомление** — AI оценивает серьезность и отправляет оповещения через каналы ботов, когда требуется действие

**Режимы уведомлений:** Отправлять всегда, при ошибке, при предупреждении, или **AI решает сам** — AI-модель оценивает вывод и автономно определяет необходимость оповещения.

### 8. MCP-сервер и AI-навыки

> Позвольте AI-клиенту управлять инфраструктурой — с тем же движком оценки рисков, согласованиями и журналом аудита, что и в веб-консоли.

EasyShell поставляется с двумя дополнительными компонентами, которые встраивают платформу в ваш AI-ассистент.

- **`easyshell-mcp`** — сервер [Model Context Protocol](https://modelcontextprotocol.io), который предоставляет хосты, скрипты, задачи и проверки EasyShell как MCP **инструменты**, поэтому Claude Desktop, Claude Code, Cursor, Cherry Studio и другие MCP-клиенты могут управлять EasyShell напрямую. Публикуется в npm как [`@easyshell/mcp-server`](https://www.npmjs.com/package/@easyshell/mcp-server), целевой сервер задаётся тремя переменными `EASYSHELL_URL` / `EASYSHELL_USER` / `EASYSHELL_PASS`. Для локальных клиентов — `npx -y @easyshell/mcp-server` (stdio), для удалённого доступа — `npx -y @easyshell/mcp-server --port 3000` (SSE + Streamable HTTP; при привязке к не-loopback адресу `--token` обязателен). Всего 20 инструментов в 3 уровнях (core 6 / management 9 / advanced 5).
- **`easyshell-skill`** — определение `SKILL.md`, которое объясняет ассистенту, **когда** и **как** использовать EasyShell (рабочие сценарии, каталог инструментов, модель безопасности). Устанавливается командой `npx mdskills install easyshell`; для OpenCode путь `.opencode/skills/easyshell/SKILL.md`, для Claude Code — `.claude/skills/easyshell/SKILL.md`.

**Текущие границы:** `easyshell-mcp` — это **исходящий** мост: он делает EasyShell *вызываемым* из AI-клиента. Использование **внешних** MCP-серверов (Prometheus, Elasticsearch или вашего собственного) *внутри* платформы EasyShell находится в роадмапе и в 1.1.0 не реализовано. Обсуждение — в [issue #6](https://github.com/easyshell-ai/easyshell/issues/6). Полный список инструментов и примеры конфигурации — в [easyshell-mcp/README.md](./easyshell-mcp/README.md).

### 9. Движок рабочих процессов (Workflow Engine)

> **Описание Workflow 2.0 см. в [README.md](README.md#9-workflow-engine) / [README.zh-CN.md](README.zh-CN.md#9-工作流引擎).** Ниже приведено описание версии 1.2.0.


> Разместите свою инструкцию на канве. Передавайте значения между узлами. Поставьте человеческий шлюз перед всем разрушительным.

Движок рабочих процессов превращает последовательность операционных шагов в **визуальный, версионируемый и аудируемый** рабочий процесс: направленный ациклический граф на интерактивной канве, где каждый узел делает одно дело и передаёт свой результат downstream-узлам. Запуск принимает типизированные входные данные, исполняется тем же путём диспетчеризации, что и скрипты, и фиксируется по каждому узлу.

**Типы узлов (пять):**

| Узел | Что делает |
|------|------------|
| `script-exec` | Выполняет скрипт на целевых хостах (явные agent’ы, кластер или тег) и порождает реальную **Task**, поэтому аудит, живые логи, сторож таймаутов и обработка отключения agent’а наследуются, а не переписываются |
| `condition` | Вычисляет выражение (`nodes.check.output.usage > 90`) и пишет булево значение в `output.result`; ветку выбирает **условие на ребре**, а не сам узел |
| `notify` | Отправляет отрендеренное сообщение в уже настроенные бот-каналы (Telegram, Discord, Slack, DingTalk, Feishu, WeCom) |
| `approval` | Приостанавливает запуск и ждёт одобрения или отклонения администратором: таймаут, необязательный обязательный комментарий и неизменяемый снимок деталей |
| `wait` | Ждёт `durationSec` (1–3600) и продолжается, проверяя отмену каждые 500 мс, поэтому отмена не застревает за сном |

**Как узлы обмениваются данными:** значения идут по рёбрам через **три канала**. **Скалярные переменные** (`run.input.<name>` / `nodes.<key>.output.<path>` / псевдонимы `outputVar`) видны только топологическим преемникам узла, снапшотятся в конце каждой волны планирования в `workflow_run.variables_json`; одно значение limitedо 8192 байтами UTF-8, большее хранится как превью «голова+хвост» с `truncated: true`. **Ссылки на артефакты** — *запланированы, не реализованы*. **Секреты** — *намеренно не реализованы*: протокол agent’а несёт только тело скрипта, поэтому внедрённый секрет попадёт в колонку скрипта задачи и будет напечатан любой командой вроде `env`. Интерполяция скрипта проходит четыре независимых слоя защиты (политика значений по белому списку → `{{NAME}}` в одинарных кавычках → проверка подстановочных интервалов на `$(`/`` ` ``/`${` → шлюз риска на узле диспетчеризации).

**Политики отказа:** `abort` (узел и всё незапущенное отменяется, запуск завершается `failed`) / `skip` (по умолчанию; узел помечается `skipped`) / `partial` (узел выполняется, вывод неудавшегося upstream считается отсутствующим). При расхождении входящих рёбер побеждает **самый строгий**; нераспознанная политика трактуется как `abort`.

**Одобрения:** узел `approval` приостанавливает запуск, **не занимая поток**: строка одобрения в БД — единственный источник истины, движок будит запуск по решению (событие в том же JVM + сканер каждые 10 с), и ничто не зависит от браузера. Единственный законный путь для скрипта не-LOW риска — одобренный узел `approval`, являющийся топологическим предком. «Отмена» означает «я больше не жду», а не «оно остановилось»: уже отправленное задание дорабатывает на хосте, а его результат отбрасывается.

**Канва:** рамментый выбор, направляющие выравнивания со снапом, привязка к сетке 20 px, отмена/возврат (Ctrl+Z / Ctrl+Shift+Z), миникарта, автоматическая раскладка (переиспользуется алгоритм глубины из представления AI-плана — без библиотеки раскладки), копирование/вставка/дублирование с регенерацией ключей, клавиатурная карта (Delete / Ctrl+A / Ctrl+S / стрелки 20 px, Shift — 4 px / Enter / Esc / Space+перетаскивание). **Канва — единственный редактор структуры, форма — единственный редактор конфигурации выбранного узла.**

**Не реализовано (роадмап):** cron- и webhook-триггеры, узлы `parallel` / `ai-analyze` / `http-request`, dry-run, replay, рынок шаблонов, хранение артефактов, внедрение секретов, продолжение running-запусков после перезапуска, слияние fan-in переменных. Эндпоинт пробного запуска одного узла есть на сервере, но ещё не подключён в UI. Запуск нескольких экземпляров сервера на одной БД — на ваш риск (движок рассчитан на одного исполнителя, межэкземплярной блокировки нет). Подробнее — в [«Workflow 从 0 到 1»](https://docs.easyshell.ai/guides/workflow/) (английский и упрощённый китайский).

## Быстрый старт

```bash
git clone https://github.com/easyshell-ai/easyshell.git
cd easyshell
cp .env.example .env      # Отредактируйте .env при необходимости
docker compose up -d
```

Локальная сборка не требуется — готовые образы автоматически загружаются из [Docker Hub](https://hub.docker.com/u/laolupaojiao).

Откройте `http://localhost:18880` → войдите как `easyshell`. При первом запуске сервер выводит сгенерированный начальный пароль в лог (или задайте его через `EASYSHELL_ADMIN_PASSWORD`) — смените его сразу после входа.

> **Хотите использовать GHCR?** Укажите в `.env`:
> ```
> EASYSHELL_SERVER_IMAGE=ghcr.io/easyshell-ai/easyshell/easyshell-server:latest
> EASYSHELL_WEB_IMAGE=ghcr.io/easyshell-ai/easyshell/easyshell-web:latest
> ```

> **Разработчик? Сборка из исходного кода:**
> ```bash
> docker compose -f docker-compose.build.yml up -d
> ```

├── easyshell-server/           # Центральный сервер управления (Java / Spring Boot)
├── easyshell-agent/            # Клиентский агент (Go, единый бинарный файл)
├── easyshell-web/              # Веб-интерфейс (React + Ant Design)
├── docker-compose.yml          # Развертывание в продакшене (готовые образы)
├── docker-compose.build.yml    # Разработка (локальная сборка из исходников)
├── Dockerfile.server           # Многоэтапная сборка Server + Agent
├── Dockerfile.web              # Многоэтапная сборка веб-интерфейса
├── .github/workflows/          # CI/CD: сборка и публикация образов Docker
└── .env.example                # Шаблон конфигурации окружения
```
